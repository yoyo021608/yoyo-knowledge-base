# MVP 功能范围

## 目标

先完成一条可运行、可追溯、可恢复的最小闭环：用户登录，收录一篇资料，提问，得到带引用的回答，刷新页面后仍能查看会话。

## 用户主流程

用户注册并登录后，完成下面一条主流程：

```text
注册/登录
→ 收录一篇文本或 Markdown 资料
→ 保存文档版本和来源
→ 完成全文与向量索引
→ 创建会话并提问
→ 混合检索并判断证据
→ 生成带引用的回答，或返回证据不足
→ 刷新页面后查看会话和引用
```

如果运行中断，用户可以继续可恢复的运行，或按事件序号查看已经产生的过程。

## MVP 必须包含

- 用户注册、登录和当前身份。
- 单篇文本或 Markdown 文档收录。
- 文档版本和来源快照保存。
- 关键词、全文和向量的混合检索接口。
- 证据过滤、上下文 token 预算和引用生成。
- 会话、消息、Citation 保存。
- Run 状态、快照和事件序号持久化。
- 断线后按 `after_seq` 回放事件，重启后从快照继续或返回可识别失败状态。
- fake 模型模式下可在本地运行和测试。

## 暂不放入 MVP

- 批量导入和失败条目重试。
- 网页抓取、复杂文件解析和对象存储。
- 文档关系图、自动专题和多 Agent 工作流。
- 多模型路由、人工审核和复杂评估后台。

## 发布判断

MVP 满足下面条件后，可以通知学长并作为第一版发布：

- 本地能够完成“注册/登录 → 收录 → 索引 → 检索 → 问答 → 引用 → 刷新后回看”。
- 证据不足、索引失败和运行失败都有明确状态，不把模型猜测当成知识库结论。
- 健康检查、后端测试、前端测试、lint 和前端构建通过。
- 后续功能通过独立 Issue 继续迭代，不为了发布提前加入 MVP 之外的功能。
