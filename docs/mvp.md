# MVP 功能范围

## 目标

提供可运行、可追溯、可恢复的知识问答闭环：用户登录，收录一篇资料，提问，得到带引用的回答，刷新页面后仍能查看会话。

## 用户主流程

用户注册并登录后，完成下面一条主流程：

```text
注册/登录
→ 收录一篇文本或 Markdown 资料
→ 保存文档版本和来源
→ 完成全文与向量索引
→ 创建会话并提问
→ 混合检索并判断证据
→ 生成带引用的回答，或返回证据不足
→ 刷新页面后查看会话和引用
```

如果运行中断，用户可以继续可恢复的运行，或按事件序号查看已经产生的过程。

## MVP 必须包含

- 用户注册、登录、注销和当前身份。
- 单篇文本或 Markdown 文档收录。
- 文档列表、详情、编辑、删除，版本与来源快照保存；编辑后只检索最新 ready 版本。
- 关键词、全文和向量的混合检索接口。
- 证据过滤、上下文 token 预算和引用生成。
- 会话、消息、Citation 保存。
- Run 状态、快照和事件序号持久化；采用单执行进程，同会话只允许一个活动 Run。
- 断线后按 `after_seq` 分页回放事件；重启复用已完成步骤，生成中断重新生成该轮，无法恢复返回明确失败。
- 用户问题及最终回答按 Run 幂等保存，回答与引用原子写入；并发领取、版本乱序、恢复重试与删除竞争纳入核心测试。
- fake 模型模式下可在本地运行和测试。

## MVP 范围之外

- 批量导入和失败条目重试。
- 网页抓取、复杂文件解析和对象存储。
- 修改密码、忘记密码、批量整理、专题标签、收藏关联和导出等扩展功能。
- 文档关系图、自动专题和多 Agent 工作流。
- 多模型路由、人工审核和复杂评估后台。

## 发布判断

MVP 发布须满足以下验收条件：

- 本地能够完成“注册/登录 → 收录 → 索引 → 检索 → 问答 → 引用 → 刷新后回看”。
- 证据不足、索引失败和运行失败都有明确状态，不把模型猜测当成知识库结论。
- 健康检查、后端测试、前端测试、lint 和前端构建通过。
- 范围外功能通过独立 Issue 管理，不纳入 MVP 验收。
